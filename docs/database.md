# Документация по Базе Данных "Король Мафии"

Версия: 1.0
Дата: 12.06.2024

Этот документ описывает структуру базы данных для проекта "Король Мафии". БД разделена на две логические части:

1.  **Система сбора статистики (Core):** Таблицы для хранения "сырых" данных о прошедших играх, турнирах и игроках (`players`, `tournaments`, `statistics` и др.).
2.  **Система Фэнтези-лиги "Король Мафии" (KM):** Таблицы, специально созданные для логики фэнтези-игры (`km_*` и `profiles`).

---

## 1. Система сбора статистики (Core)

Эти таблицы служат источником данных для расчета рейтингов и других показателей.

### Таблица `players`

Хранит информацию о всех реальных игроках в мафию. Является центральной таблицей для идентификации игроков.

| Колонка              | Тип           | Описание                                                                                         |
| -------------------- | ------------- | ------------------------------------------------------------------------------------------------ |
| `id` (PK)            | `integer`     | Уникальный идентификатор игрока.                                                                 |
| `name` (UNIQUE)      | `text`        | Уникальный никнейм игрока.                                                                       |
| `official_rating`    | `real`        | **(Для фэнтези)** Текущий официальный рейтинг игрока. Пересчитывается после каждого турнира.     |
| `win_percentage`     | `real`        | **(Для фэнтези)** Текущий процент побед. Пересчитывается после каждого турнира.                  |
| `avg_dop_points`     | `real`        | **(Для фэнтези)** Среднее количество доп. баллов за игру. Пересчитывается после каждого турнира. |
| `total_games_played` | `integer`     | **(Для фэнтези)** Общее количество сыгранных игр. Используется для расчета `Power Score`.        |
| `created_at`         | `timestamptz` | Дата и время создания записи.                                                                    |
| `updated_at`         | `timestamptz` | Дата и время последнего обновления записи.                                                       |

### Таблица `tournaments`

Хранит информацию обо всех реальных турнирах по мафии.

| Колонка         | Тип                      | Описание                                                                                                    |
| --------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `id` (PK)       | `integer`                | Уникальный идентификатор турнира.                                                                           |
| `name` (UNIQUE) | `text`                   | Название турнира.                                                                                           |
| `url`           | `text`                   | Ссылка на источник данных о турнире (например, для парсера).                                                |
| `isFinished`    | `boolean`                | Флаг, указывающий, завершен ли турнир (используется текущей системой).                                      |
| `isVisible`     | `boolean`                | Флаг, указывающий, видим ли турнир (используется текущей системой).                                         |
| `start_date`    | `date`                   | **(Для фэнтези)** Дата начала турнира.                                                                      |
| `status`        | `tournament_status_enum` | **(Для фэнтези)** Текущий статус турнира в фэнтези-лиге (`Планируется`, `Идет`, `Завершен`, `Архивирован`). |

### Другие таблицы Core

- **`games`**: Список всех игр, сгруппированных по сессиям.
- **`sessions`**: Игровые сессии/дни внутри одного турнира.
- **`statistics`**: Детальная статистика по каждому игроку в каждой игре (очки, роли, карточки и т.д.). **Основной источник данных для расчетов.**
- **`positions`**: Итоговые места игроков в рамках сессий.
- **`roles`**: Справочник игровых ролей (Мафия, Дон, Шериф и т.д.).
- **`fantasy_users` / `fantasy_picks`**: Таблицы существующей фэнтези-системы. **Не используются в "Короле Мафии".**

## 2. Система Фэнтези-лиги "Король Мафии" (KM)

Эти таблицы обеспечивают работу новой фэнтези-платформы.

### Таблица `km_tournament_participants`

Связывает игроков и турниры, определяя, кто участвовал в каком турнире.

| Колонка              | Тип       | Описание                                                                          |
| -------------------- | --------- | --------------------------------------------------------------------------------- |
| `id` (PK)            | `integer` | Уникальный идентификатор записи.                                                  |
| `tournament_id` (FK) | `integer` | Ссылка на `tournaments.id`.                                                       |
| `player_id` (FK)     | `integer` | Ссылка на `players.id`.                                                           |
| `final_rank`         | `integer` | Итоговое место, занятое игроком на реальном турнире. Заполняется администратором. |
| `dop_points_earned`  | `real`    | Сумма доп. баллов, заработанных за турнир. Заполняется администратором.           |

### Таблица `km_pre_tournament_stats`

**Ключевая таблица фэнтези.** Хранит "замороженный" слепок статов игрока на момент начала турнира. Это обеспечивает историческую точность.

| Колонка              | Тип       | Описание                                                                         |
| -------------------- | --------- | -------------------------------------------------------------------------------- |
| `id` (PK)            | `integer` | Уникальный идентификатор записи.                                                 |
| `tournament_id` (FK) | `integer` | Ссылка на `tournaments.id`.                                                      |
| `player_id` (FK)     | `integer` | Ссылка на `players.id`.                                                          |
| `calculated_raw_ps`  | `real`    | Рассчитанный `Power Score` игрока **перед** началом турнира.                     |
| `tier`               | `text`    | Присвоенный игроку тир (`Легенда`, `Золото` и т.д.) на основе его `Power Score`. |
| `salary`             | `integer` | Виртуальная зарплата игрока, рассчитанная для этого турнира.                     |

### Таблица `km_tier_configs`

Таблица-справочник. Хранит правила для расчета тиров и зарплат. **Не имеет прямых связей (FK)**, так как используется кодом для расчетов.

| Колонка                 | Тип       | Описание                                                              |
| ----------------------- | --------- | --------------------------------------------------------------------- |
| `id` (PK)               | `integer` | Уникальный идентификатор правила.                                     |
| `tier_name` (UNIQUE)    | `text`    | Название тира (`Легенда`, `Бриллиант` и т.д.).                        |
| `rank_start_percentage` | `real`    | Начальный процент ранга для этого тира (например, 0 для топ-игроков). |
| `rank_end_percentage`   | `real`    | Конечный процент ранга для этого тира (например, 2 для топ 2%).       |
| `min_salary`            | `integer` | Минимальная зарплата для этого тира.                                  |
| `max_salary`            | `integer` | Максимальная зарплата для этого тира.                                 |
| `is_active`             | `boolean` | Флаг, позволяющий временно отключать правило.                         |

### Таблица `profiles`

Хранит публичную информацию о пользователях системы (администраторах и будущих игроках фэнтези).

| Колонка       | Тип              | Описание                                                                                                                             |
| ------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `id` (PK, FK) | `uuid`           | Уникальный идентификатор пользователя. **Напрямую связан с `auth.users(id)` из системы Supabase Auth.** `ON DELETE CASCADE` включен. |
| `role`        | `user_role_enum` | Роль пользователя в системе (`SuperAdmin`, `Editor`, `User`). Определяет права доступа.                                              |

## 3. Пользовательские типы данных (ENUMs)

Для обеспечения целостности данных в системе созданы следующие перечисляемые типы (`ENUM`).

### `tournament_status_enum`

Определяет возможные статусы турнира в фэнтези-лиге.

| Значение        | Описание                                   |
| --------------- | ------------------------------------------ |
| `'Планируется'` | Турнир создан, но еще не начался.          |
| `'Идет'`        | Турнир активен, идет прием фэнтези-команд. |
| `'Завершен'`    | Турнир окончен, результаты подсчитаны.     |
| `'Архивирован'` | Турнир скрыт из основного списка.          |

### `user_role_enum`

Определяет роли пользователей в системе, которые используются для разграничения прав доступа (RLS).

| Значение       | Описание                                                                          |
| -------------- | --------------------------------------------------------------------------------- |
| `'SuperAdmin'` | Имеет полный доступ ко всем функциям админ-панели, включая настройки.             |
| `'Editor'`     | Может управлять игроками и турнирами, но не имеет доступа к системным настройкам. |
| `'User'`       | Обычный пользователь фэнтези-лиги.                                                |

## 4. Триггеры Базы Данных

Триггеры используются для автоматизации процессов на уровне базы данных, обеспечивая надежность и целостность данных.

### Триггер `on_auth_user_created`

- **Событие:** Срабатывает `AFTER INSERT` (после вставки) новой записи в системную таблицу `auth.users`.
- **Действие:** Вызывает функцию `handle_new_user()`.
- **Назначение:** **Автоматически создать запись в `public.profiles` для нового зарегистрированного пользователя.** Это ключевой механизм, который связывает систему аутентификации Supabase с нашей публичной информацией о пользователях. Функция `handle_new_user()` берет `id` и `username` (из метаданных) нового пользователя и создает для него профиль с ролью `'User'` по умолчанию.
